# SWT release-evidence core 0.1.0: what is frozen

Status: **Initial freeze as 0.1.0, not 1.0.0.** Frozen by owner ruling F8 and the owner's instructions of 2026-11-21 and 2026-11-22. Promotion to 1.0.0 requires a consumer profile that passes conformance and a pinned real-adopter validation. No tag or release is made by this change.

Artifact: [`schemas/release-evidence.core.0.1.0.schema.json`](../../schemas/release-evidence.core.0.1.0.schema.json), with its recorded sha256 in `schemas/release-evidence.core.0.1.0.schema.json.sha256` (hash of the file with CRLF normalised to LF; `.gitattributes` keeps the schema LF). The drift test in `test/core-schema-conformance.test.mjs` detects a mismatch between the schema and its recorded hash (decision S19b: vendored versioned copy, hash, drift test). It does not stop someone editing both files: a change to a file named 0.1.0 is a reviewable diff and by policy needs a new version, but that is not enforced by the test. Consumers vendor the file with its hash.

## Frozen in 0.1.0

1. **The single envelope with per-kind branches.** One envelope, one entry of `testRuns[]`, with `evidenceKind` of `automated` or `manual`. Both branches require `testId`, `evidenceKind` and `artifactDigest`. The `automated` branch requires `command` (non-blank string) and `exitCode` equal to `0`. The `manual` branch carries neither `command` nor `exitCode`. A `manual: true` entry may not be labelled `automated`; when present, `manual` is a boolean.
2. **`tests[]` and `testRuns[]`.** `tests[]` is the list of **required test identities**: a non-empty array of objects, each with a unique non-blank string `id`. `testRuns[]` is **execution evidence**: each run is one envelope (item 1) bound to a required test by `testId`. Every required test must map to at least one run with its `id`; an unmatched requirement cannot pass (not-evaluated below production, rejected at production). A run whose `testId` names no required test is rejected. When `testRuns` is present at the top level it is an array. The content of a run beyond item 1 is not defined in 0.1.0. Extra fields on a `tests[]` entry are ignored, so execution evidence placed there counts for nothing.
3. **`source.dirty`.** A boolean, required at every stage. `true` is invalid only at stage `production`.
4. **The `not-evaluated` outcome.** An absent required field below stage `production` is not-evaluated, never pass. At stage `production` it rejects. A present but invalid value always rejects. `pass` requires no errors and nothing not-evaluated. The set that is required at stage `production` is part of this item: the `artifact` group with a non-blank `artifact.digest`; a non-empty `tests[]` with an `id` each; `testRuns[]` covering every test; the `signing` group with `signing.status`; `source` with `dirty`; and, per run, `testId`, `evidenceKind` and `artifactDigest` plus the branch fields of item 1. The enums are frozen too: stage `internal`, `test`, `staged`, `production`; `signing.status` `not-evaluated`, `attested`, `ingested`, `failed`.
5. **Signing never passes by being unevaluated.** A declared `signing.status` of `not-evaluated` yields the verdict `not-evaluated`, at every stage, unless signing is explicitly not applicable with a declared, attested basis: `signing.notApplicable` is an object with non-blank string `basis` and `attestedBy`, valid only together with status `not-evaluated`. A blank or malformed `notApplicable`, or one alongside any other status, rejects. The schema describes the shape of `notApplicable`; the verdict rule is the evaluator's. A declared `signing.status` of `failed` rejects at every stage (owner ruling of 2026-11-22), even when all other evidence passes; it is an evaluator rule, as the schema describes present values only.
6. **`residualRisks[]`.** The plural core name; when present at the top level it is an array. Its content is not defined or validated in 0.1.0 and the schema does not require it.
7. **The `evaluate()` result shape.** `{ verdict, errors, notEvaluated }` where `verdict` is `pass`, `reject` or `not-evaluated`, and `errors` and `notEvaluated` are arrays of strings. A non-object record is rejected with `record must be an object`. The record must be plain JSON data: accessor properties, proxies, a `toJSON` (enumerable or not), class instances, array subclasses, objects from another realm (a null-prototype one is plain data), boxed primitives, built-ins that `util.types` identifies as having internal slots, such as Date, Map, Set, Promise and typed arrays (even with a swapped prototype), any own key named `toJSON` (even a plain data value), extra array properties, non-enumerable own properties or array indices, symbol-keyed properties, non-finite numbers and `undefined`, function or symbol values are rejected without invoking anything, and the record is evaluated and secret-scanned as one JSON snapshot. A globally polluted `Object.prototype` or `Array.prototype` is out of scope, and so is an object whose hidden state no reflective API exposes (private fields, a `WeakRef`, a `URL`, an `Intl` object) placed behind a deliberately swapped prototype: it is indistinguishable from `{}` and holds no property the record is read through.

The evaluator checks that a `notApplicable` basis and an attester are declared, not that either is true. A declared but false attestation is a matter for the human reviewer, as with every attestation.

## Not frozen, still open

- Retention, approvals, rollback, provenance and distribution validation.
- The required fields of the manual branch (who performed the procedure, the procedure reference).
- The amendment of charter Standard 02, which says manual and automated evidence "use separate schemas", against ruling F2. The charter has not been amended by this change.
- Anything else not listed above, including run fields other than those in item 1 (`startedAt`, `finishedAt`, `environment`, `result`, `retention`), `source.revision`, `artifact.id` and `schemaVersion`.
- What makes a run "applicable" beyond the `testId` binding. In 0.1.0 a run counts for its test when its `testId` matches, and a run that is itself invalid (wrong digest, failing exit code, wrong branch fields) makes the record reject, so it cannot satisfy a requirement.
- The secret scan, the digest-equality rule between `artifact.digest` and `testRuns[].artifactDigest`, the test-id and mapping rules as schema rules (they are evaluator-only), the record depth and size limits, and the profile-redefinition rule. These live in the experimental checker and are not part of the frozen schema; the scan is defence in depth, and a non-detection is not proof that no secret is present.
- Apple and Android release profiles: each must pin `coreVersion` 0.1.0 and pass conformance before anything is promoted to 1.0.0.

## What the schema does and does not express

The schema describes present values. It cannot say "absent is not-evaluated" or "every test has a run"; those are the evaluator's contract (items 2, 4 and 5). The conformance test requires, for every fixture, that the schema accepts the present values of each pass and not-evaluated fixture, and rejects each reject fixture whose reason is structural. Fixtures whose only reasons are evaluator-only rules (secret scan, digest equality, test mapping, the two signing verdict rules, profile redefinition, record limits) are not compared against the schema.

## Changes in this PR beyond the schema

The experimental checker moves the envelope checks from `tests[]` to `testRuns[]`, adds identity, uniqueness and mapping checks, adds the signing rule, rejects a top-level `testRuns` or `residualRisks` that is present but not an array, and its header points at this freeze. All existing fixtures were migrated mechanically (each former test entry became an identity plus a run, and a declared `not-evaluated` signing status became `attested` in every migrated fixture except those about signing itself); new fixtures cover mapping and signing.
